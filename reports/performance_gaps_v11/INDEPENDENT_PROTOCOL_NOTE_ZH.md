# 独立评测执行细则，尚未打开测试

这份执行细则在首批训练和DEV审议完成之前登记，不按独立测试结果挑模型。
先读取完整100K训练代价与五个DEV节点；再决定是否在900K上限内登记有依据的小候选；
最后将三条线的完整配对、对应检查点SHA256、原生收据SHA256、DEV审议文件SHA256统一冻结。
未完成这一步时，独立评测程序拒绝运行。

每模型每条件100个保留的新独立布局，CPU上运行，重置每回合动作RNG：
`independent_action_seed + condition_index*1000 + episode_index`。
同任务各方法共享布局和动作seed，全部仅部署既有target Actor；不与online混合。
首批六个端点共2000回合。若后续候选取代首批某分支，必须先重新登记兼容的配对与完整身份；
当前实现只接受首批原生v11格式，不能把未知修订模型静默加载成P5。

为分析Payload能否保留速度，再测**以前已经固定**的Piper Iso60K参考，额外300回合、零训练步。
身份为`c69d8daa…88359d2`，不是重新搜索历史检查点。该参考也使用共同target部署，
因此不照搬旧online评测的40.5%优势数字，须按本轮同一新布局重新计算。
它的历史候选年龄与P5/EA不同，只是速度参考，不是同轮训练预算的因果对照。
固定动作尺度1.0，执行085条件仍按原条件缩放，不做新的尺度扫描。

总计2300回合只涉及300个不同布局seed（三任务各100，条件与方法复用），
不能当作2300个独立训练样本或跨seed稳定性证据。
静态接纳失败原seed原样登记、不替换；报告attempted/admitted与共同接纳分母。
实际违规、超时、所有失败的horizon封顶用时均保留，路径包含初始任务位置。
相近观测违规率只作描述，不宣称风险等价；不能只对成功回合计算速度优势。

每条线在全局freeze旁写独占`independent_consumed_<line>.json`，同freeze换输出路径也不会自动再测。
工程失败保留已消耗标记，不自动重试；最终结果不反馈给本轮训练选择。
大型轨迹只留数据盘。程序为`evaluate_native_p5_adaptation.py`；当前没有执行独立仿真。
